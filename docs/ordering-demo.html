The ordering storefront

A minimal customer face over the live API — not a simulation. Every button below is a real HTTP call: the fee you see comes from the pricing engine (surge tiers and coupon codes included), the driver assignment is the geolocation dispatcher, and the timeline is the event log the warehouse consumes.

checking…

1 · Basket

Loaded from GET /customers and GET /restaurants.

2 · Price the delivery

POST /pricing/quote — dropoff prefills from the customer; a coupon code becomes an auditable discount line. Omitting demand lets the API derive it live from the demand forecasts.

3 · Sign in & place the order

Order creation is a write, so it needs a token — the demo trio is ops/ops (or admin/admin); viewers correctly get 403. POST /orders quotes the fee again server-side.

4 · Track the lifecycle

Polled from GET /orders/{id} every few seconds — the same event log Kafka relays to the warehouse. Operator buttons are writer-only.
